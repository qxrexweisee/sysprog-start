# Монитор процессов Windows

## 1. Описание проекта

Программа предназначена для мониторинга запущенных процессов операционной системы Windows.

Основная задача — отслеживать потребление оперативной памяти (RAM) и процессорного времени (CPU), сохранять историю измерений и обнаруживать изменения состояния процессов.

Особое внимание уделяется идентификации процессов: несколько экземпляров одной программы могут иметь одинаковое имя, а после перезапуска процесс получает новый PID.

## 2. Возможности

- Получение списка запущенных процессов.
- Отслеживание PID и имени процесса.
- Сбор статистики использования CPU.
- Сбор статистики потребления оперативной памяти.
- Сохранение истории измерений в CSV-файл.
- Определение появления новых процессов.
- Обнаружение завершения процессов.
- Различение нескольких экземпляров программы с одинаковым именем.
- Анализ истории потребления RAM.
- Выявление процессов с наибольшим ростом потребления памяти.

## 6. Идентификация процессов

Одной из основных особенностей проекта является различение процессов с одинаковыми именами.

Использование только имени процесса недостаточно, поскольку одновременно могут работать несколько экземпляров одной программы.

Также нельзя использовать только PID, поскольку после завершения процесса операционная система может повторно использовать этот идентификатор.

Для идентификации экземпляров используется составной ключ, включающий:
- имя процесса;
- PID;
- время создания процесса.

Таким образом, два одновременно работающих экземпляра одной программы рассматриваются как разные процессы. После перезапуска старый экземпляр считается завершённым, а новый регистрируется отдельно.

## 7. Проведённые эксперименты

### Эксперимент 1. Мониторинг запущенных процессов

После запуска программы был получен список процессов Windows с указанием:
- PID;
- имени;
- загрузки CPU;
- потребления RAM.

В одном из измерений было обнаружено 229 процессов.

### Эксперимент 2. Несколько экземпляров одной программы

Были запущены два экземпляра Блокнота Windows (`notepad.exe`).

Монитор обнаружил оба процесса с разными PID:

```text
[НОВЫЙ ПРОЦЕСС] notepad.exe PID=16684
[НОВЫЙ ПРОЦЕСС] notepad.exe PID=10576
```

После завершения первого экземпляра и повторного запуска:

```text
[НОВЫЙ ПРОЦЕСС] notepad.exe PID=14332
[ЗАВЕРШЕН] notepad.exe PID=16684
```

В результате монитор корректно определил два одновременно работающих экземпляра и отдельно зарегистрировал новый экземпляр после перезапуска.

В истории было зафиксировано три различных экземпляра `notepad.exe`.

### Эксперимент 3. Имитация постепенного роста потребления RAM

Для проверки обнаружения постепенного увеличения потребления оперативной памяти была создана тестовая программа `memory_leak_test.py`.

Она постепенно выделяет память блоками по 10 МБ с интервалом 5 секунд.

Результаты эксперимента:

| Шаг | Выделено памяти | Потребление RAM |
|---|---:|---:|
| 1 | 10 MB | 24.75 MB |
| 5 | 50 MB | 64.79 MB |
| 10 | 100 MB | 114.78 MB |
| 15 | 150 MB | 164.80 MB |

Монитор зарегистрировал тестовый процесс:

```text
python.exe
PID: 15732
Измерений: 14
RAM: 34.76 -> 164.80 MB
Рост: +130.04 MB
```

Таким образом, программа успешно обнаружила постепенное увеличение потребления оперативной памяти тестовым процессом.
